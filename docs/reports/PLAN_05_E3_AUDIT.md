# 方案 05 E3 自审计

2026-11-20 · HolderProof 本地 fixture P0

本轮沿用三个成员、两份相同完整事实达成一致的委员会规则。自动验收覆盖
事件内容、委员会聚合、证书校验和两个 Gate 的资格动作。报告中的
“本地网络”指官方四节点 localnet，其中三个节点加入业务委员会。

| 检查 | 验证层级 | 判定依据 |
|---|---|---|
| 同区块多笔转入转出及边界 | Indexer guest | 乱序输入按 logIndex 恢复，块前余额为 0，块内两笔转账均计入余额 |
| 修改一条 fixture Transfer 的金额 | Python | 重算的事件 Merkle 根与原值不同 |
| 一份提案有异议、两份正确事实一致 | Indexer guest | 两份一致提案仍能选出完整事实 |
| 三份提案分歧、重复成员、checkpoint 不一致 | Indexer guest | 按当前 2-of-3 门槛无法得到一致事实 |
| 错误区块哈希、余额或事件根变化、签名不足、非 Finalized | Gate guest | 共享证书校验拒绝输入 |
| 重复相同查询 | 本地网络 | 两个独立 Gate 使用同一证书，重复查询保持证书内容和创建位置 |
| 无历史记录的 holder | 本地网络 | 有效证书记录余额 0，正门槛下资格不足 |
| 领取与投票 | 本地网络 | 不足门槛及非对应 holder 的请求均不产生动作。满足门槛的对应 holder 各成功一次，重复请求不增加计数 |
| 成员进程暂停与恢复 | 本地网络 | 对新查询分别观察暂停一名和暂停两名成员的结果，恢复后验证可认证 |
| Gate 配置权限 | 本地网络 | 非初始化者提交的配置请求不改变门槛 |
| 撤销权限与撤销结果 | 本地网络 | 非初始化者操作后证书仍有效。初始化者撤销后，证书仅状态改变，两个 Gate 均不再记录基于该证书的动作 |

对于本地网络请求，Anvil 回执仅用于确认排序成功。脚本等待后续
Lyquid 状态提交，再读取资格状态、动作计数和证书。此方法用于验证
最终可观察行为，证据中保留交易哈希便于回查。

两个用于动作测试的持有者来自本机 Anvil 测试账户。它们在 fixture
中的余额是 0，因此脚本先用门槛 1 验证拒绝，再用门槛 0 验证领取或
投票的成功路径。撤销场景用一个尚未领取或投票的 holder，避免已有
记录触发去重规则而掩盖撤销检查。

## 复现

从仓库根目录运行，确保本地 demo 使用的端口空闲。

```bash
make e3
./scripts/stop-step4.sh
```

`make e3` 先运行 `make acceptance`，再操作新启动的本地 Gate
和证书。验收结束后本地实例保持启动，便于检查状态。
证据保存在 `.run/acceptance/e3-results.json`，属于本地运行产物。
本轮运行日志位于 `.run/acceptance/e3-final.log`。

## 方案核对

执行方案 05 写着一名错误节点会导致无法达到 2/3。如果其余两名成员
对同一完整事实达成一致，原方案的 2-of-3 规则已满足。验收按这个规则：
正确的两份一致时允许认证，任意两份都不一致时拒绝认证。

P0 对于“未确认区块”的可测试边界是 fixture 最后一个区块 1000。
超出范围的查询及错误的区块哈希均被拒绝。实际链的区块重组和最终性
仍属于真实数据源接入后的验证。P0 证明历史持仓事实，信用评分还需要
价格、借款、还款和清算数据等独立输入。

## 验收结果

2026-11-20 从全新本地环境运行 `make e3` 通过，包括 25 项 Rust guest、
6 项 Python、9 项 fixture 检查和 18 次历史 EVM 余额对照。CLI 另验证了
区块 1001 会被拒绝。两个 Gate 各记录一次有效动作，资格不足、身份
不符、重复操作和撤销均未增加动作计数。

暂停一名委员会成员时，其余两名成员为新查询生成了有效证书，证书有
两名签名者。暂停两名成员时，调用在 25 秒后超时，随后 5 秒内仍无
证书。恢复成员后，同一查询生成有效证书。对于暂停一名成员时已完成
的查询，恢复后重复提交保持原证书。两组测试的进程都已恢复。

## 适用范围

- 证书输入和委员会分歧的负例在 Python 或 guest 层执行。本地网络覆盖权限、证书生命周期和成员暂停恢复。
- Gate 的 `/api/result` 保存上次成功检查的诊断结果，当前证书状态应从 Indexer 获取。领取和投票每次重新读取并验证证书。
- 认证依赖配置的 Indexer、Lyquor 原生运行时和至少两名诚实成员。重放依赖完整 Transfer 历史，缺失日志或共享实现错误会影响所有节点。独立 Python 标准答案和历史 EVM 对照用于发现余额偏差。
- 数据集是确定性 fixture，适用于标准 ERC-20 余额语义。特殊代币行为、Sepolia 最终性和脱离原生运行时的签名鉴定需要独立验证。
- 方案 06 要求至少三位团队外参与者完成查询和资格判断。已准备[独立试用任务单](../guides/EXTERNAL_USER_TEST.md)，真实参与者记录尚未收到。
